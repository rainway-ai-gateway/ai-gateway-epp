# 场景说明：SC16 指标导出

所属场景编号：SC16；代码目录：`test/implementation/scenario-SC16-metrics-export`（包名 `sc16`）。

## 1. 背景与目的

本次改动（2026-10-19，设计见 `docs/zh_cn/modifications/2026-10-19-epp-metrics/`）修复了 EPP 指标导出：

- `:9004/metrics` 只导出 controller-runtime 的 registry，而组装入口从未注册 llm-d 的 `llm_d_epp_*` 采集器，导致运行时 `Record*` 写入但从不导出；
- 池聚合 7 指标（`ready_endpoints` / `average_*` / `std_dev_*`）的唯一生产者（per-cell 刷盘循环）从未启动；
- 端点级排队数需要一个对多 cell（多 datastore）友好的暴露方式。

本场景验证这组改动的可观测结果：`llm_d_epp_*` 注册生效、端点级指标按 cell/endpoint 产出、池聚合指标按集群产出、相关配置项被接受、新鲜端点驱动池聚合产出。

## 2. 运行模式

- **TC-01~TC-04：本地配置文件模式**（harness `common.NewLocalEnv`，`--local-config-dir`）。不启动 inference-sim：cluster_table 端点为**保留回环端口**（`FindFreePort` 返回后即关闭监听），只验证指标导出与配置项，不访问推理后端。因此**无 sim 依赖、可稳定运行**。
- **TC-05：完整模式**（harness `common.NewEnv`，mock InnerAPI + inference-sim）。验证数据源抓取 sim `/metrics` 后端点"新鲜"，池聚合随之产出；sim 二进制缺失时 `t.Skip`。

## 3. TC 列表

| 编号 | 名称 | 断言要点 |
|---|---|---|
| TC-01 | 采集器注册与导出 | `/metrics` 出现 `llm_d_epp_info`（注册生效的证据）；`llm_d_epp_datalayer_poll_errors_total{source_type="metrics-data-source"}` 出现（数据层导出链路生效）；`ai_epp_*` 无回归 |
| TC-02 | 端点级排队指标 | 多 cluster/多端点：`ai_epp_per_endpoint_queue_size` 每个端点一条，标签 `{cluster,inference_pool,model_server_endpoint}` 正确，值 0（未访问后端） |
| TC-03 | 池聚合指标按集群 | `llm_d_epp_ready_endpoints{name=<cluster>}` 每集群出现且为 0；无新鲜端点时 `average_*` / `std_dev_*` **不出现**（而非导出误导性的 0） |
| TC-04 | 指标相关配置项 | 带 `-pool-metrics-flush-interval` / `-pool-metrics-staleness-window` / `-fairness-id-metric-label-limit` 启动：进程 SERVING，指标照常导出 |
| TC-05 | 新鲜端点驱动池聚合 | 数据源抓取 sim 后：`ready_endpoints` ≥ 1，`average_kv_cache_utilization` 出现（需 inference-sim） |

## 4. 观测指标

| 指标 | 标签 | 说明 |
|---|---|---|
| `llm_d_epp_info` | build_ref, commit | 启动写 1；其存在即证明 `llm_d_epp_*` 采集器已注册 |
| `llm_d_epp_datalayer_poll_errors_total` | source_type | 数据层抓取失败计数（本场景端点不可达 → 递增） |
| `ai_epp_per_endpoint_queue_size` | cluster, inference_pool, model_server_endpoint | 端点级排队数（本次新增） |
| `llm_d_epp_ready_endpoints` | name | 池内"指标新鲜"的端点数（`name` = 集群） |
| `llm_d_epp_average_*` / `llm_d_epp_std_dev_*` | name | 池聚合；仅在存在新鲜端点时产出 |
| `ai_epp_cell_state` | cluster, state | 回归对照：ai-gateway 自有指标持续导出 |

## 5. 依赖与就绪

- harness 自动构建 epp 二进制（无 ldflags → `llm_d_epp_info` 的 build_ref/commit 为空字符串，断言只判存在性）。
- 就绪门控：本地模式 `WaitHealth` SERVING；**指标产出可能滞后于就绪**（刷盘循环默认 5s），测试用 `-pool-metrics-flush-interval=200ms` 加速并以 `WaitFor` 轮询，不做一次性断言。
