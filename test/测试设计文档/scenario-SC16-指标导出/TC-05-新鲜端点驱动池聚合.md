# TC-05 新鲜端点驱动池聚合

| 项 | 内容 |
|---|---|
| 用例编号 / 名称 | TC-05 / 新鲜端点驱动池聚合 |
| 所属场景 | SC16 指标导出 |
| 版本 | v0.1 |

## 测试目的

验证池聚合的完整链路：当数据源成功抓取后端 `/metrics`、端点指标变得"新鲜"后，`ready_endpoints` 反映端点数，且 `average_*` / `std_dev_*` 聚合家族随之产出（区别于 TC-03 的"无新鲜端点 → 不产出"）。

## 运行模式

完整模式（`common.NewEnv`）：mock InnerAPI + 每个逻辑后端一个 inference-sim（真实进程）+ epp。**需要 inference-sim 二进制**，缺失时用例 `t.Skip`。以 `-pool-metrics-flush-interval=200ms -pool-metrics-staleness-window=5s` 加速刷盘并放宽新鲜窗口。

## 前置条件

1. harness 已构建 epp 二进制；inference-sim 二进制可用。
2. mock API 已配置 assignment、epp_config（cluster-a 最小配置）与 cluster_table（cluster-a 2 个 sim 后端）。
3. epp 已启动并就绪，数据源已开始抓取 sim 的 `/metrics`。

## 测试步骤

| # | 操作 | 预期 |
|---|---|---|
| 1 | 抓取 `/metrics`，检查 `llm_d_epp_ready_endpoints{name="cluster-a"}` | 30s 内 ≥ 1（端点指标新鲜后计入就绪数） |
| 2 | 检查 `llm_d_epp_average_kv_cache_utilization{name="cluster-a"}` | 30s 内出现（`podCount > 0` 触发聚合产出） |
| 3 | 检查端点级指标 | `ai_epp_per_endpoint_queue_size` 覆盖 cluster-a 的两个 sim 端点 |

## 预期结果

- `ready_endpoints` 随抓取新鲜度上升；`average_*` 家族出现。
- 端点级指标与池聚合指标共存，构成"池 ↔ 端点"视图。

## 清理

`defer e.Close()`：Kill epp 与 sim 进程并 Wait，关闭 mock API；`t.TempDir` 自动清理。
